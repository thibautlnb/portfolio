Semestre 1 Développement WebHTML / CSS

Projet 1.4 — Se présenter sur Internet

1Description & Objectif

Dans le cadre de cette SAÉ (SAÉ 1.04 / SAE14), j'ai conçu et entièrement développé un site internet multipages composé de 5 pages sémantiques distinctes, dédié à ma passion : la musculation et le bodybuilding. L'objectif principal était de construire un site web moderne, adaptatif (Responsive Web Design), respectueux des standards du W3C et accessible (normes WCAG 2.0 AA), tout en apprenant à piloter mon environnement et mes versions de fichiers de manière professionnelle.

2Apprentissages Critiques

  • AC13.01 : Identifier les différents composants d'un système numérique. Maîtrise globale de l'environnement client-serveur. Compréhension du rôle du navigateur (moteur de rendu côté client) et de l'hébergement cloud distant mis en place pour le projet via le service GitHub Pages.
  • AC13.04 : Connaître l'architecture et les technologies d'un site Web. Découverte et mise en application pratique de l'architecture sémantique HTML5 associée aux propriétés CSS3 avancées (utilisation de Flexbox pour l'alignement des éléments et gestion adaptative globale via Media Queries).
  • AC13.06 : S'intégrer dans un environnement propice au développement. Initialisation et exploitation d'un dépôt Git local et distant (GitHub). Gestion structurée de l'avancement à l'aide de commits porteurs de sens, rédaction d'un fichier de documentation centralisé (README.md) et utilisation d'outils de planification (Rétroplanning XLSX).

3Tâches réalisées & Preuves

Le projet a été mené de manière méthodique en suivant les 3 grandes étapes recommandées : la phase de conception (définition de la charte graphique et de l'architecture de l'information), la phase de développement technique (codage HTML/CSS des sections), et la phase de validation de conformité (W3C/WCAG).

Preuve #01 : Architecture multipages sémantique et Documentation (README.md) Le site s'appuie sur une structure modulaire de 5 fichiers HTML interconnectés, associés à un dossier CSS contenant des feuilles de style dédiées par page afin d'appliquer une identité visuelle propre (grâce à des linear-gradients spécifiques) :

- index.html (Accueil - Hub central) 🔴 - pratique.html (Styles d'entraînement : Bodybuilding, Powerlifting, Street Workout, CrossFit) 🔵 - materiel.html (Guide complet des équipements et accessoires) 🟣 - nutrition.html (Macronutriments, guides de Prise de masse et de Sèche) 🟢 - Apropos.html (Profil personnel, Personal Records et programme interactif) 🟠

L'ensemble du projet a été poussé en ligne et rendu accessible au public à l'adresse de déploiement GitHub Pages officielle : https://thibautlnb.github.io/site-internet/.
Preuve #02 : Algorithme d'interactivité graphique en CSS Pur (Extrait de Apropos.html) Pour intégrer une animation interactive sans JavaScript, j'ai implémenté un système de carrousel (slider) 100 % CSS. Celui-ci exploite les liaisons sémantiques entre des balises masquées <input type="radio"> et leurs labels correspondants pour faire glisser la piste interne (.inner-track) : 
<!-- Structure de contrôle du Carrousel Push / Pull / Legs -->
<input type="radio" name="slider" id="slide1" checked>
<input type="radio" name="slider" id="slide2">
<input type="radio" name="slider" id="slide3">

<div class="slides-inner">
    <div class="inner-track">
        <div class="slide"><div class="training-card"><h3>Jour Push</h3>...</div></div>
        <div class="slide"><div class="training-card"><h3>Jour Pull</h3>...</div></div>
        <div class="slide"><div class="training-card"><h3>Jour Legs</h3>...</div></div>
    </div>
</div>
En CSS, la translation s'effectue dynamiquement lors du changement d'état (exemple : #slide2:checked ~ .slides-inner .inner-track { transform: translateX(-33.33%); }), offrant une navigation fluide.
Preuve #03 : Validation Technique et Accessibilité Standards Afin de valider la conformité technique demandée dans les critères d'évaluation : 1. Validation W3C : Chaque page a été soumise au validateur officiel (W3C Markup Validation Service) afin de nettoyer les balises obsolètes et garantir un code HTML5/CSS3 valide et sans erreurs. 2. Accessibilité WCAG 2.0 AA : Utilisation systématique de l'attribut alt explicite sur l'intégralité des images du site (ex: alt="Image d'un Bodybuilder" ou alt="image de macronutriments") pour permettre la lecture correcte par les synthèses vocales des personnes malvoyantes.

4Autoévaluation & Réflexion

Ce que j'ai appris

Ce projet m'a permis de comprendre l'intérêt fondamental de la sémantique HTML5 (utiliser <header>, <main>, <section>, <footer>) pour structurer proprement un document. J'ai également appris à maîtriser Flexbox pour concevoir des grilles de cartes d'équipements ou d'entraînements fluides et adaptatives. Enfin, l'usage régulier des commandes Git m'a sensibilisé aux bonnes pratiques du versionnage de code.

⚠Difficultés rencontrées ✓Solutions apportées
#01 Sensibilité à la casse lors du déploiement (Linux/Serveur)

En local sous Windows, les liens vers les pages fonctionnaient correctement. Cependant, suite au premier déploiement sur les serveurs de GitHub Pages, le lien de navigation vers la page "À propos" renvoyait une erreur 404.

 #01 Uniformisation des chemins de fichiers

J'ai identifié que mon fichier source était nommé avec une majuscule (Apropos.html) tandis que certains appels ou feuilles de style étaient écrits différemment. Les serveurs d'hébergement Linux étant sensibles à la casse, j'ai corrigé tous mes liens de navigation sémantiques dans mes balises <nav> pour pointer strictement vers le nom exact du fichier.
#02 Création d'interactivité graphique sans JavaScript

L'obligation d'apporter de l'interactivité (notamment pour présenter mes 3 programmes de musculation Push, Pull et Legs) sans utiliser de scripts JavaScript représentait une contrainte importante au Semestre 1.

 #02 Détournement des éléments de formulaire "Radio"

J'ai utilisé l'astuce des boutons radio CSS masqués (display: none). En reliant des boutons fléchés (<label>) aux ID des boutons radio grâce à l'attribut for, le clic change l'état coché du bouton. Le sélecteur CSS de frère général (~) m'a permis de modifier dynamiquement la position (transform: translateX) du bloc de cartes de manière fluide.
